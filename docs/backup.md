# 原稿のバックアップ

`src/posts/` の原稿（記事フォルダと `order.json`）を、Cloudflare R2 バケットにバックアップします。

## 事前準備

1. Cloudflare ダッシュボードの R2 で、バックアップ用のバケットを作成します（公開アクセスは無効のままで問題ありません）。
2. API トークンに「Workers R2 ストレージ:編集」権限を付与します。公開用のトークンに追加するか、専用のトークンを新規作成してください。
3. `.env` にバケット名を設定します。

```sh
ESSAIS_R2_BACKUP_BUCKET=essais-backup
# R2 用に別のトークンを作った場合（未設定時は CLOUDFLARE_API_TOKEN を使用）
# ESSAIS_R2_TOKEN=...
```

## バックアップの実行

`pnpm run deploy` 実行時、デプロイ完了後に自動でバックアップが走ります。
`ESSAIS_R2_BACKUP_BUCKET` が未設定の場合は、バックアップを行わずデプロイのみを完了します。
バックアップ処理に失敗した場合、サイトの公開は完了していてもコマンドの終了コードは失敗（エラー）となります。

単独でバックアップを実行することも可能です。

```sh
pnpm backup             # 変更のあったファイルのみアップロード
pnpm backup --dry-run   # 対象ファイルの一覧を表示して終了（通信のみ確認）
```

アップロードされるのは、R2 上のファイルと内容が異なる差分ファイルのみです。
ローカルで削除したファイルは、誤削除時の復元を可能にするため、R2 側からは削除されずに保持されます。

## バックアップからの復元

新しい PC でリポジトリを clone した場合などは、R2 から原稿データを復元できます。

```sh
pnpm backup --pull --dry-run   # 復元対象のファイル一覧を表示して終了
pnpm backup --pull             # R2 からローカルへ復元
```

R2 にのみ存在するファイル、および内容に差分があるファイルを `src/posts/` に上書き・追加します。
ローカルにのみ存在する新規ファイルは削除されず保持されます。

R2 のデータを正としてローカルを同期するため、まだバックアップしていないローカルの変更内容は R2 のデータで上書きされます。
ローカルで執筆中の原稿がある場合は、事前に `--dry-run` を実行し、`update` と表示されるファイルがないか確認してください。
